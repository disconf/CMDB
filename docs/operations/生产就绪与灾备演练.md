# 生产就绪与灾备演练

## 上线前检查

访问“系统管理 → 生产就绪”，确认 PostgreSQL、pgvector、Redis、Kafka、Keycloak、Vault、MinIO/S3、Prometheus、Alertmanager、Argo CD、Rancher 检查结果。

阻断项必须全部解决；Loki、Neo4j、OpenSearch、Temporal 等可选组件未部署时显示为提示。

## 备份与恢复

```bash
bash scripts/production/backup-postgres.sh
bash scripts/production/restore-postgres.sh backups/ops-platform-YYYYMMDD-HHMMSS.sql.gz
```

备份文件同时生成 SHA256 校验文件。恢复前必须先在隔离环境验证。

## 压力测试

```bash
k6 run -e BASE_URL=http://172.28.69.164:30080 -e ACCESS_TOKEN=... scripts/production/load-test-assets.js
k6 run -e BASE_URL=http://172.28.69.164:30080 -e AGENT_SHARED_TOKEN=... scripts/production/load-test-agent-heartbeat.js
```

资产查询目标：P95 小于 800ms，错误率小于 1%。Agent 心跳目标：100 次/秒持续 2 分钟，错误率小于 1%。

## 安全冒烟

```bash
VIEWER_TOKEN=... ADMIN_TOKEN=... bash scripts/production/security-smoke.sh
```

至少验证未认证访问被拒绝、只读用户不能创建任务、管理员可访问生产就绪报告。

## 灾备演练

1. 备份 PostgreSQL 并校验 SHA256。
2. 在隔离命名空间恢复数据库并运行 `go test ./...`。
3. 停止一个网关副本，验证服务仍可用。
4. 模拟 Redis 节点故障，验证会话和远程终端降级策略。
5. 模拟 Kafka Broker 故障，验证 Outbox 积压恢复。
6. 模拟 Prometheus/Loki 不可用，验证网关核心写入不受影响。
7. 记录恢复时间目标 RTO 和恢复点目标 RPO，形成演练报告。
