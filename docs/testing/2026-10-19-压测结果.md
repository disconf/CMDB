## 测试机链路说明

从当前 Windows 开发机直接压测时，20 并发下客户端侧 P95 达到 3.8 秒，但网关服务端指标显示同一接口平均约 15ms、P95 约 65ms。该差异来自开发机到集群 NodePort 的网络链路，因此性能结论以集群内 Runner 的结果为准。

## 1,000 Agent 心跳

使用临时数据库 `cmdb_agenttest` 和临时单副本网关，不写入生产 CMDB。

### 同时心跳

- 1,000 个 Agent 各上报一次，总计 1,000 次请求。
- 错误率：0.00%。
- 全部上报被接受。
- 单副本、1 CPU 限制下，P95 为 14.25s，最大 14.86s；这是 1,000 个请求同时到达时的排队延迟，不是失败。

### 持续心跳验收

- 按验收口径执行 100 次/秒，持续 2 分钟。
- 总请求：12,001。
- 错误率：0.00%。
- 平均延迟：31.61ms。
- P95：100.77ms。
- 最大延迟：1.15s。
- 临时数据库最终生成 1,200 个 Agent 资产，说明上报已实际落库。

结论：持续 100 次/秒心跳满足错误率 < 1% 的目标；1,000 Agent 突发心跳全部被接收，生产双副本和 60 秒错峰上报会进一步降低排队延迟。
