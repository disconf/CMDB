# 知识库模块完善设计

> 状态：**P0/P1 已实施，P2 部分完成**。已上线网关 `1.0.230` / 门户 `1.0.180`。
> 日期：2026-10-19
> 范围：知识库目录、文档编辑、版本、权限、检索和 RAG 权限隔离

## 1. 现状与差距

现有知识库已经具备：

- 知识条目新建、编辑、删除、草稿/发布。
- 标签、分类、关联资产/工单/告警。
- Markdown 预览、附件、版本历史和版本还原。
- 关键词 + 向量混合检索、RAG 问答、引用和反馈。

目前主要缺口：

| 事项 | 现状 | 本次设计 |
| --- | --- | --- |
| 目录 | 只有单层 `category` 文本 | 多级目录树，支持新建、重命名、移动、删除 |
| 文档编辑 | 普通 textarea，保存后关闭弹窗 | 独立编辑页，Markdown 分栏预览、自动保存、冲突提示 |
| 权限 | 只有 `aiops:view` / `aiops:execute` 两级 | 功能权限 + 目录/文档 ACL + 项目组数据范围 |
| 更新 | 有 PUT 更新和版本历史 | 增加草稿、发布、归档、移动、回收站和版本差异 |
| 检索 | 只按关键词和分类 | 目录范围检索、权限过滤、最近访问和收藏 |
| RAG | 检索结果未按当前用户权限过滤 | 检索、引用和问答全部经过权限过滤 |

## 2. 目标

1. 知识库可长期维护，而不是只能靠单个文本分类字段。
2. 文档有清晰的目录归属和可追踪的编辑、发布、归档生命周期。
3. 权限在服务端强制执行，目录和文档都能按用户、角色、项目组授权。
4. 编辑体验接近常见文档系统：自动保存、版本对比、冲突提示、附件和预览。
5. AI 检索和 RAG 只能引用当前用户有权查看的文档。

## 3. 信息架构

### 3.1 一级导航

知识库作为一级菜单，内部包含：

| 区域 | 内容 |
| --- | --- |
| 目录树 | 全部目录、项目组目录、我的文档、最近访问、收藏 |
| 文档列表 | 当前目录下的文档，支持搜索、状态和标签筛选 |
| 文档详情 | 正文、目录、元数据、附件、关联对象、版本、权限 |
| 编辑器 | 新建/编辑文档，Markdown 分栏预览，保存草稿或发布 |

### 3.2 推荐前端布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 知识库  搜索  新建目录  新建文档  导入  刷新                  │
├──────────────┬──────────────────────────┬───────────────────┤
│ 目录树        │ 文档列表                  │ 文档详情/编辑器     │
│ 全部          │ 标题 / 状态 / 负责人       │ 标题、正文、目录     │
│ 项目组        │ 更新时间 / 浏览量          │ 附件、关联、版本     │
│ 我的文档      │                          │ 权限、发布、归档     │
│ 最近访问      │                          │                   │
│ 收藏          │                          │                   │
└──────────────┴──────────────────────────┴───────────────────┘
```

窄屏下目录树折叠为抽屉，文档详情改为单栏。

## 4. 数据模型

### 4.1 知识目录

新增 `knowledge_folders`：

| 字段 | 说明 |
| --- | --- |
| id | 目录 ID |
| parent_id | 父目录，根目录为空 |
| name | 目录名称 |
| path | 物化路径，例如 `/ops/database/mysql` |
| description | 目录说明 |
| sort_order | 排序 |
| visibility | private / project / organization |
| owner | 负责人 |
| created_by / created_at / updated_at | 审计字段 |
| deleted_at | 软删除时间 |

约束：

- 同一父目录下名称唯一。
- 禁止把目录移动到自己的子目录。
- 默认最多 5 级，后续可配置。

### 4.2 知识文档

在现有 `aiops_knowledge` 基础上扩展，保持现有 ID 和 RAG 索引兼容：

| 新增字段 | 说明 |
| --- | --- |
| folder_id | 所属目录 |
| slug | 文档稳定标识，用于链接 |
| content_md | Markdown 正文，替代原 `content` 的编辑字段 |
| status | draft / published / archived |
| visibility | private / project / organization |
| owner | 文档负责人 |
| created_by / updated_by | 创建人、最后修改人 |
| current_version | 当前版本号 |
| published_version | 当前发布版本号 |
| sort_order | 目录内排序 |
| deleted_at | 软删除时间 |

现有 `category` 字段保留用于兼容和快速展示，值由所属目录或根目录派生，不再作为唯一组织方式。

### 4.3 权限 ACL

新增 `knowledge_acl`：

| 字段 | 说明 |
| --- | --- |
| id | ACL ID |
| resource_type | folder / document |
| resource_id | 目录或文档 ID |
| subject_type | user / role / project_group |
| subject_id | 用户 ID、角色名或项目组编码 |
| permission | view / edit / publish / manage |
| effect | allow / deny |
| inherit | 是否向下继承 |
| created_by / created_at | 审计字段 |

### 4.4 版本、附件和收藏

- `aiops_knowledge_versions` 继续保存快照，增加 `folder_id`、`permission_snapshot`、`change_summary`。
- `aiops_knowledge_attachments` 继续使用 MinIO/S3，增加文档权限校验。
- 新增 `knowledge_favorites`：用户收藏文档。
- 新增 `knowledge_recent_views`：最近访问，按用户保存，定期清理。
- 可选新增 `knowledge_comments`，评论不进入 RAG 向量。

## 5. 权限模型

### 5.1 功能权限

在现有 RBAC 基础上增加：

| 权限 | 能力 |
| --- | --- |
| knowledge:view | 查看有权访问的已发布文档 |
| knowledge:create | 新建目录和文档 |
| knowledge:edit | 编辑自己有权限的文档 |
| knowledge:publish | 发布、下架、归档 |
| knowledge:delete | 删除或移入回收站 |
| knowledge:manage_acl | 修改目录/文档权限 |
| knowledge:manage_folder | 新建、移动、重命名、删除目录 |

现有 `aiops:view` 自动映射为 `knowledge:view`，`aiops:execute` 自动映射为知识库管理员能力，保证升级后现有用户可用。

### 5.2 数据权限

采用“目录继承 + 文档覆盖”：

1. 先取用户所属角色、项目组和用户 ID。
2. 从根目录向下解析继承 ACL。
3. 文档自身的 ACL 优先于目录 ACL。
4. `deny` 优先于 `allow`。
5. 草稿默认仅作者、具备编辑权限的人和知识库管理员可见。
6. 已发布文档按 `visibility + ACL` 判断可见范围。

### 5.3 权限矩阵建议

| 角色 | 查看发布 | 查看草稿 | 编辑 | 发布 | 管理权限 |
| --- | --- | --- | --- | --- | --- |
| 普通用户 | 按 ACL | 否 | 否 | 否 | 否 |
| 项目组编辑 | 按 ACL | 本组草稿 | 本组文档 | 否 | 否 |
| 项目组发布者 | 按 ACL | 本组草稿 | 本组文档 | 本组文档 | 否 |
| 知识库管理员 | 全部 | 全部 | 全部 | 全部 | 全部 |

## 6. 目录与文档操作

### 6.1 目录

- 新建根目录或子目录。
- 重命名、修改说明、排序。
- 拖拽移动目录。
- 删除目录时要求目录为空，或选择“移动到父目录”。
- 目录详情显示子目录、文档数、负责人和权限摘要。
- 面包屑导航和目录搜索。

### 6.2 文档

- 新建文档时选择目录。
- 文档可移动、复制、归档、恢复和软删除。
- 支持批量移动、批量归档和批量删除。
- 文档详情展示负责人、状态、更新时间、版本、标签和关联对象。
- 支持从 AIOps 分析、告警、工单生成草稿。
- 支持从 CSV/Markdown 批量导入。

### 6.3 回收站

- 文档和目录删除后进入回收站，默认保留 30 天。
- 回收站只对知识库管理员可见。
- 恢复时检查父目录是否存在，不存在则恢复到根目录。
- 超过保留期自动清理，操作写入审计。

## 7. 编辑、发布与版本

### 7.1 编辑器

- 独立编辑页，不放在弹窗内。
- 左侧 Markdown 编辑，右侧实时预览。
- 工具栏：标题、粗体、斜体、代码、链接、列表、表格、引用、图片/附件。
- 保存草稿、发布、预览、关闭。
- 自动保存：编辑停止 20 秒或切换页面前保存草稿。
- 显示“已保存 / 保存中 / 有未保存修改 / 保存失败”状态。

### 7.2 并发编辑冲突

- 文档保存携带 `current_version`。
- 服务端版本不一致时返回 409。
- 前端展示“服务器版本已更新”，提供查看差异、覆盖或基于最新版本继续编辑。
- 不允许静默覆盖他人修改。

### 7.3 发布

- 草稿保存不对外可见。
- 发布后进入已发布状态，并按权限对外提供检索。
- 可选目录级审批：开启后，编辑者提交发布申请，发布者审批后生效。
- 归档后不再出现在默认列表和 RAG 检索中，但历史仍可查。

### 7.4 版本

- 每次保存草稿、发布、移动、权限变更都记录版本或操作历史。
- 版本列表显示版本号、修改人、修改摘要、时间和状态。
- 支持版本差异查看：标题、摘要、正文、标签、目录、权限。
- 支持还原到历史版本，还原生成新版本，不覆盖历史。

## 9. 前端交互

### 9.1 目录树

- 支持展开/收起、拖拽移动、右键菜单。
- 目录节点显示文档数、草稿数和权限标记。
- 当前目录高亮，面包屑同步。
- 目录树滚动独立，文档列表滚动独立。

### 9.2 文档列表

- 列：标题、状态、负责人、更新时间、浏览量、标签。
- 支持按状态、标签、负责人、更新时间筛选。
- 支持列表/卡片视图切换。
- 支持批量选择和批量操作。

### 9.3 文档详情

- 顶部显示目录面包屑、标题、状态和权限标记。
- 右侧目录导航随正文滚动高亮。
- 操作：编辑、发布、归档、移动、复制、版本、权限、删除。
- 附件支持拖拽上传、下载和删除。
- 关联资产/工单/告警支持跳转。

### 9.4 编辑器

- 全屏编辑页或占据主内容区，不遮挡目录树。
- 标题、目录、摘要、标签、权限在头部表单。
- Markdown 分栏预览，支持全屏预览。
- 自动保存状态和最后保存时间清晰可见。
- 离开有未保存内容时二次确认。

## 10. 检索与 RAG 权限隔离

这是本次必须补齐的安全项。

1. 文档保存后更新关键词索引和向量索引。
2. 搜索先按目录范围、状态和用户有效权限过滤，再做关键词/向量排序。
3. RAG 问答只召回当前用户可查看的已发布文档。
4. 引用列表和回答中不得出现无权文档的标题、正文或片段。
5. AI Agent 的知识工具调用同样传入当前用户身份。
6. 普通用户不能通过猜测文档 ID 直接读取详情或附件。

## 11. 审计与安全

审计事件：

- 目录新建、重命名、移动、删除、权限变更。
- 文档新建、保存草稿、发布、归档、恢复、移动、复制、删除。
- 版本还原和权限变更。
- 附件上传、下载、删除。
- 草稿查看和回收站恢复。

安全要求：

- Markdown 渲染继续先转义再渲染，或使用成熟 Markdown + HTML 清洗库。
- 附件校验大小、类型和文件名；下载必须校验文档权限。
- 权限判断只在服务端做最终决定。
- RAG 和搜索日志不记录文档正文和敏感凭据。

## 12. 迁移方案

1. 新增目录、ACL、收藏和最近访问表。
2. 为现有 `aiops_knowledge.category` 每个取值创建一个根目录。
3. 将现有文档的 `folder_id` 指向对应目录，保留原 ID、版本、附件和向量索引。
4. 现有已发布文档默认授予 `aiops:view` 用户查看权限。
5. 现有草稿默认只对原作者和 `aiops:execute` 用户可见。
6. 保留旧接口返回字段，新增字段以可选方式返回，避免前端和 RAG 立即失效。

- RAG/Agent 全链路权限过滤和回归测试。

## 14. 验收标准

1. 目录支持至少 5 级嵌套，可新建、重命名、拖拽移动和删除。
2. 文档可移动到任意有权限的目录，移动后列表、面包屑和 RAG 结果同步更新。
3. 编辑页支持 Markdown 分栏预览和自动保存。
4. 两人同时编辑同一文档时不会静默覆盖，能查看冲突。
5. 目录和文档权限对用户、角色、项目组均可配置，且继承关系可预测。
6. 普通用户无法通过 ID 直接读取无权文档或附件。
7. RAG 问答和引用不会泄露无权文档。
8. 所有变更可在审计日志中追溯到操作人、时间和对象。
9. 现有知识文档、版本、附件和向量索引在迁移后不丢失。

## 15. 待确认事项

1. **知识库形态**：采用单一知识库 + 多级目录，还是多知识空间 + 多级目录？建议先单一知识库，后续再加空间。
2. **编辑器形态**：Markdown 优先，还是需要接近 Word 的富文本编辑器？建议 Markdown 优先，便于版本、检索和 RAG。
3. **权限粒度**：是否确认“目录继承 + 文档覆盖 + deny 优先”？建议确认。
4. **发布审批**：是否需要目录级可选的发布审批？建议保留为可选配置。
5. **个人文档**：是否允许每个用户有私有文档目录？建议允许，默认不对他人可见。
6. **回收站**：删除文档保留 30 天是否合适？
7. **附件限制**：单附件 20MB、常见文档/图片类型是否足够？
8. **评论与协同**：本期是否需要评论、@提醒或多人实时协同？建议放到 P2。
9. **外部分享**：是否需要公开链接或跨组织分享？建议首期不做。

## 16. 本次已实施

- 多知识空间：组织空间、项目组空间、用户私有空间；私有空间按用户自动创建。
- 多级目录树：目录创建、重命名、移动、删除、排序、按目录递归查询文档。
- 文档编辑：Markdown 分栏预览和富文本 contenteditable 双模式；切换模式会转换内容格式。
- 文档生命周期：草稿、发布、归档、更新、负责人、可见范围和版本号。
- 权限：功能权限 + 目录/文档 ACL，支持用户、角色、项目组，允许/拒绝及向下继承；私有空间隔离。
- 版本历史：复用原有版本表，支持查看和还原。
- 附件：复用原有 MinIO 附件接口，文档详情内支持上传、下载和删除。
- 前端：知识空间切换、目录树、文档列表/详情、编辑页、权限弹窗、版本面板和知识问答入口。
- 迁移：旧 `category` 自动映射为默认空间下的目录，旧文档自动归属，原 ID、版本、附件和向量索引保留。
