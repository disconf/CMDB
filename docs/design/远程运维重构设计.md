# 远程运维重构设计

## 1. 目标与范围

远程运维面向“安全接入、可审计、可回放、可协作”的日常运维场景，覆盖：

- WebSSH 交互终端
- 文件上传与下载
- 批量远程执行
- 高风险命令审批
- 终端录像、命令审计与回放
- 协作者接入与强制断开
- 主机指纹与 SSH 凭据管理
- 终端安全策略、策略模板与批量分发

设计原则：

1. **安全边界在服务端**：前端拆分只改变交互，不降低资产授权、路径校验、命令拦截和审计要求。
2. **一个任务一个工作区**：终端、文件、批量执行、审批、录像、策略不再挤在同一屏。
3. **多副本可协同**：会话、票据、租约和终端输出必须跨网关副本保持一致。
4. **默认留痕**：会话建立、输入输出、审批、文件传输、断开和归档均写入审计。
5. **失败可恢复**：网络抖动自动重连；节点失联由租约机制回收；录像可归档、可导出、可按保留期清理。

## 2. 前端信息架构

远程运维作为一级菜单，二级菜单与路由保持一一对应：

| 菜单 | 路由 | 职责 |
|---|---|---|
| 概览 | `/remote/overview` | 会话、执行、审批、安全状态汇总与快捷入口 |
| 终端会话 | `/remote/sessions` | 建立/恢复会话、WebSSH、协作者、强制断开 |
| 文件传输 | `/remote/files` | 在策略允许的路径与大小内上传、下载 |
| 批量执行 | `/remote/execution` | 按项目组、标签、IP/CIDR 选择目标并执行 |
| 审批与审计 | `/remote/approvals` | 高风险命令审批、历史会话、录像回放、导出 |
| 安全设置 | `/remote/security` | 账户授权、主机指纹、安全策略、模板与批量分发 |

前端组件按工作区拆分，避免继续膨胀单文件：

- `RemoteAccessPage.vue`：工作区外壳、标题和二级导航
- `RemoteSessionWorkspace.vue`：会话列表 + 终端工作区
- `RemoteFileWorkspace.vue`：文件传输
- `RemoteApprovalWorkspace.vue`：审批与审计
- `RemoteRecordingWorkspace.vue`：录像回放与导出
- `RemoteSecurityWorkspace.vue`：授权、指纹、策略、模板
- `useRemoteTerminal.ts`：WebSocket 连接、重连、心跳和终端生命周期

当前阶段先完成可靠性修复；组件物理拆分可按上述边界渐进实施，避免一次性重写带来回归风险。

## 3. 终端会话全链路

```text
选择资产/凭据
  → 创建会话（PostgreSQL 持久化）
  → 申请一次性票据（Redis，60 秒有效）
  → WebSocket 升级（任意网关副本）
  → 原子兑换票据（GETDEL）
  → 获取会话租约（owner_node + lease_expires_at）
  → SSH 建链并创建 PTY
  → 输入/输出写 remote_terminal_events
  → 关闭 → 会话状态更新 → 录像归档 MinIO
```

### 3.1 一次性票据

- 票据由 32 字节随机数生成，仅通过 HTTPS 返回给当前浏览器。
- 票据存储在 Redis：`cmdb:remote:ticket:{ticket}`，TTL 60 秒。
- 兑换使用 `GETDEL` 原子操作，保证多副本下也只能成功一次。
- Redis 明确返回不存在或 Redis 异常时均拒绝，不回退到本地内存，避免重复使用。
- 仅当未配置共享总线（单副本/开发模式）时才使用进程内票据。

### 3.2 WebSocket 升级

- 网关链路中的日志、指标、审计和追踪中间件必须透传 `http.Hijacker`。
- 追踪中间件的 `statusRecorder` 已补充 `Hijack`、`Flush`、`Unwrap`，否则 WebSocket 升级会返回 HTTP 500。
- 升级成功后先下发 `ready`，随后输出终端数据；错误以 `error` 消息返回，不直接断开无提示。

### 3.3 自动重连与心跳

- 前端每 25 秒发送应用层 `heartbeat`，保持代理和连接活跃。
- 非用户主动关闭时，按 1s、2s、4s、8s、15s 指数退避自动重连，最多 6 次。
- 每次重连重新申请票据，不复用旧票据。
- 用户主动关闭、切换到其他会话或离开页面时取消重连定时器和心跳。
- 连续重连失败后提示“请手动重新连接”，保留终端历史输出。

### 3.4 会话租约

- 会话拥有者通过 `owner_node` 标识，租约默认 45 秒，可配置 `REMOTE_SESSION_LEASE_TTL`。
- 终端通道每 `TTL/3`（默认 15 秒）续期一次。
- 网关副本崩溃后，租约过期由任意副本的 `ReconcileRemoteSessionLeases` 回收，会话标记为 `interrupted`。
- 网关正常退出时主动释放本副本拥有的会话。
- 多副本终端输出通过 Redis Pub/Sub 转发；控制输入按 owner 路由，避免多写。

## 4. 录像与审计

### 4.1 事件模型

`remote_terminal_events`：

| 字段 | 说明 |
|---|---|
| session_id | 会话 ID |
| sequence | 会话内单调递增序号 |
| direction | input / output |
| data | 终端数据（当前为文本，后续可扩展为 base64） |
| created_at | 事件时间 |

录像按 `(session_id, sequence)` 排序回放，支持：

- 在线回放（`GET /remote-sessions/{id}/terminal-recording`）
- 文本导出（`/terminal-recording/export`）
- 命令日志导出（`/command-log/export`）
- MinIO 归档（`POST /remote-sessions/{id}/archive`）

### 4.2 归档

- 归档对象包含会话元数据、事件流和校验信息。
- 写入 MinIO 后记录 `archive_bucket`、`archive_key`、`archive_sha256`、`archive_size`、`archived_at`。
- 归档失败记录 `archive_status=failed` 和 `archive_error`，由后台任务重试。
- 按 `recording_retention_days` 定时清理过期对象，并记录 `archive_deleted_at`。
- 审计要求：归档、导出、删除均写审计日志。

### 4.3 回放体验

- 时间轴显示输入、输出、审批、阻断和文件传输节点。
- 支持 1x/2x/4x 倍速、暂停、拖动定位。
- 回放只读，不允许向目标主机发送输入。
- 录像与命令日志分离展示：录像看“发生了什么”，命令日志看“执行了什么”。

## 5. 审批与安全策略

### 5.1 审批

- 策略 `approval_mode=risk`：仅高风险命令进入审批。
- 策略 `approval_mode=all`：所有输入命令均需审批。
- 审批单包含会话、资产、命令、原因、申请人、过期时间。
- 审批通过后在原终端继续执行；拒绝或超时则阻断。
- 审批状态实时推送到终端（`approval_required`）和审批工作区。

### 5.2 命令拦截

服务端维护危险命令规则，至少覆盖：

- 递归删除系统目录
- 格式化文件系统、修改分区、覆写块设备
- 关机、重启、终止 init/systemd
- Fork Bomb、递归开放根目录权限

拦截结果写入会话日志和审计，不能只依赖前端提示。

### 5.3 文件传输

- 受 `fileTransferEnabled`、`uploadMaxMB`、`downloadMaxMB` 控制。
- 上传/下载路径必须匹配策略白名单。
- 文件名、路径和大小在服务端二次校验。
- 传输记录写入审计，支持按会话追溯。

### 5.4 主机指纹

- 首次连接记录主机公钥指纹。
- 指纹变化时阻断连接并要求管理员确认。
- 指纹与资产、主机、端口绑定，支持查看、信任和删除。

### 5.5 账户授权

- 授权维度：用户/角色 × 项目组/标签/资产 × 权限（terminal/file）。
- 会话创建时校验资产范围，越权直接拒绝。
- 协作者分 `control` 与 `readonly`，只读协作者不能发送输入。
- 支持强制断开、协作者移除和会话并发上限。

## 7. 数据模型

核心表：

- `remote_access_sessions`：会话主表，含 owner_node、lease_heartbeat_at、lease_expires_at、archive_* 字段
- `remote_terminal_events`：终端输入/输出事件流
- `remote_terminal_approvals`：高风险命令审批单
- `remote_security_policies`：用户/角色/全局策略
- `remote_security_policy_templates` / `_versions`：策略模板与版本回滚
- `remote_host_keys`：主机指纹
- `remote_access_grants`：账户授权范围

索引建议：

- 会话：`(status, lease_expires_at)`、`updated_at DESC`
- 事件：`(session_id, sequence)` 主键、`(session_id, created_at)`
- 审批：`(status, updated_at DESC)`、`(session_id, updated_at DESC)`

## 8. 部署与运行要求

- 网关至少 2 副本，共享 Redis 与 PostgreSQL。
- Redis 必须是健康集群或单实例；集群需覆盖 16384 个槽位。
- 终端总线通过 `REMOTE_TERMINAL_REDIS_URL` 配置，生产环境保持 `REMOTE_TERMINAL_BUS=enabled`。
- MinIO 用于录像归档，需配置 bucket、访问密钥和 CA。
- 网关配置 `SSL_CERT_FILE` 以信任内部 HTTPS 服务。
- 追踪开启时必须验证 WebSocket 升级链路。

## 9. 验收标准

1. 任意网关副本签发票据，另一副本可成功升级为 `101 Switching Protocols`。
2. 同一票据第二次兑换必须返回 401。
3. 终端保持 75 秒以上仍可执行命令，租约持续续期。
4. 断网/重启副本后，前端自动重连并恢复终端；超过重试次数给出明确提示。
5. 会话关闭后录像可在审批与审计工作区回放、导出。
6. 高风险命令在审批通过前不会发送到目标主机。
7. 越权资产、越权路径、超大文件均被服务端拒绝。
8. 主机指纹变化时连接被阻断并可人工确认。
9. 所有会话、审批、文件传输、导出和策略变更均可在审计中追溯。
