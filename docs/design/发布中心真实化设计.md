# 发布中心真实化设计

## 1. 目标

发布中心不再使用内存演示数据，而是以 PostgreSQL 为事实源，接收 GitLab CI、Harbor 和 Argo CD 的发布事件，形成统一的发布流水线、制品和阶段视图。

## 2. 数据模型

### release_deployments

保存一条发布流水线：

- 应用、版本、环境和前序版本
- 状态、进度、操作人、发布策略和审批状态
- 关联工单
- 事件来源 `source` 和外部发布 ID `externalId`
- 提交号 `commit`
- JSONB 阶段列表

### release_artifacts

保存制品：

- 应用、版本、提交号
- 制品大小、安全扫描结果和 URL
- 事件来源
- 创建时间

制品按“应用 + 版本 + 提交号”去重。

## 3. 事件接口

```text
POST /api/v1/releases/events
X-Release-Token: <RELEASE_WEBHOOK_TOKEN>
Content-Type: application/json
```

公共字段：

```json
{
  "source": "gitlab|harbor|argocd",
  "externalId": "pipeline-123",
  "type": "pipeline|artifact|deployment|scan",
  "application": "payment-gateway",
  "version": "v4.2.0",
  "environment": "production",
  "status": "running|success|failed|rolling-back|cancelled",
  "stage": "build|scan|artifact|deploy|verify|rollback",
  "progress": 70,
  "message": "image pushed",
  "commit": "31bd808",
  "size": "194 MB",
  "security": "passed",
  "url": "harbor.example.com/...",
  "ticketId": "TKT-20260915-001",
  "operator": "gitlab-ci"
}
```

## 4. 合并规则

- 发布流水线按 `externalId + application + version + environment` 合并。
- 阶段按 `stage` 更新；同阶段重复上报覆盖最新状态和进度。
- 状态统一映射到平台状态，便于前端展示。
- Harbor 和 Argo CD 携带相同提交号时只保留一个制品记录。
- 发布事件和操作审计写入 `audit_log`。

## 5. 集成方式

### GitLab CI

在流水线阶段调用：

```yaml
curl -fsS -X POST "$CMDB_RELEASE_EVENT_URL" \
  -H "X-Release-Token: $CMDB_RELEASE_EVENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"source":"gitlab","externalId":"'$CI_PIPELINE_ID'","type":"pipeline","application":"'$CI_PROJECT_NAME'","version":"'$CI_COMMIT_TAG'","environment":"production","status":"running","stage":"build","progress":20}'
```

### Harbor

通过 Harbor Webhook 或 CI 步骤上报制品：

- `source=harbor`
- `type=artifact`
- `commit` 使用镜像标签中的提交号
- `security` 使用扫描结果

### Argo CD

通过 Notification 或 CI 步骤上报同步状态：

- `source=argocd`
- `type=deployment`
- `stage=verify` 或 `deploy`
- `status` 使用 `success/failed/running`

## 6. 安全边界

- 事件接口必须携带 `RELEASE_WEBHOOK_TOKEN`。
- Token 只保存在 Kubernetes Secret，不写入前端、日志或 Git。
- 发布中心仍受 `release:view` / `release:manage` 权限控制。
- 发布事件只更新发布和制品投影，不直接执行部署命令。
