# 远程运维前端导航设计

## 1. 目标

把原先集中在一个长页面里的终端、文件、批量执行、审批、录像和安全策略拆成独立工作区，减少同屏信息密度，同时保持操作上下文和安全边界清晰。

## 2. 二级菜单

远程运维作为一级菜单，展开后包含：

| 菜单 | 路由 | 主要职责 |
|---|---|---|
| 概览 | `/remote/overview` | 展示远程运维能力和各工作区入口 |
| 终端会话 | `/remote/sessions` | 建立会话、WebSSH、协作者管理和在线会话控制 |
| 文件传输 | `/remote/files` | 在策略允许的路径和大小范围内上传、下载文件 |
| 批量执行 | `/remote/execution` | 按项目组、标签或 IP/CIDR 解析目标并提交审批执行 |
| 审批与审计 | `/remote/approvals` | 高风险命令审批、历史会话、命令回放和终端录像 |
| 安全设置 | `/remote/security` | 账户授权、主机指纹和终端安全策略 |

`/remote` 自动跳转到 `/remote/overview`，所有子路由继承 `discovery:view` 权限。

## 3. 页面分层

- 顶部保留当前工作区标题、说明和三项安全能力提示。
- 顶部二级导航与侧边栏二级菜单使用同一份配置，避免路由和文案漂移。
- 每个页面只渲染本工作区需要的卡片，避免连接、审批、录像和策略同时抢占视觉空间。
- Agent 与发现页面不再重复承载“受控运维”入口，远程能力统一从远程运维菜单进入。

## 4. 操作流

```text
概览
  → 终端会话（建立会话、连接 WebSSH）
  → 文件传输（围绕当前会话执行受控上传/下载）
  → 批量执行（选择目标和操作、提交审批）
  → 审批与审计（审批风险命令、回放会话）
  → 安全设置（授权范围、主机指纹、策略模板与批量分发）
```

## 5. 安全展现原则

- 当前账号生效策略始终在会话和文件区域可见。
- 高风险命令以审批状态展示，不把审批操作藏在终端输出中。
- 历史录像、命令日志和归档状态统一放在审批与审计工作区。
- 策略模板、版本、批量分发和策略变更审计统一放在安全设置工作区。
- 服务端仍需执行资产授权、路径校验、命令安全校验和审计写入，前端拆分不改变后端安全边界。
