# CMDB 商业授权与资产额度设计

> 版本：V1.0
>
> 更新日期：2026-10-22
>
> 免费额度：200 个资产

## 1. 产品规则

平台采用“开源社区版 + 商业授权”模式：

- 社区版不限制使用时间，最多管理 200 个资产；
- 第 201 个新资产开始需要商业许可证；
- 商业许可证可配置 201 到 10,000,000 个资产；
- 许可证可设置有效期，也可以签发永久许可证；
- 资产额度按部署实例统计，不按用户或项目组统计；
- 到期后默认宽限 30 天，可通过 `LICENSE_GRACE_DAYS` 修改；
- 额度不足时只阻止新增，不删除、不隐藏已有资产；
- 编辑、查询、导出和删除已有资产继续可用。

当前 V1 将 `cmdb_assets` 中每一条资产记录计为一个额度。K8s Pod、
Namespace、Service、Workload、PV 和 PVC 同样计入额度。这样规则简单且可审计，
但大量采集 K8s 子资源时会快速消耗额度；后续如有需要，可引入
`cmdb_models.license_counted` 对资产模型配置计费权重。

## 2. 总体架构

```text
客户平台                         独立授权站
┌──────────────────┐            ┌──────────────────┐
│ Deployment ID    │──申请文件──▶│ 管理员登录          │
│ 内置 Ed25519 公钥 │            │ Ed25519 私钥签名   │
│ 导入许可证        │◀─.license──│ 签发记录与下载      │
│ PostgreSQL 状态   │            └──────────────────┘
└──────────────────┘
```

正式平台只包含公钥，不能自行生成商业许可证。授权站与运维门户分开部署，
私钥仅挂载到授权站容器。

## 3. 许可证格式

许可证采用紧凑的离线签名格式：

```text
CMDB-LIC-v1.<base64url(payload)>.<base64url(signature)>
```

签名算法为 Ed25519，签名内容为 `CMDB-LIC-v1.<payload>`。

Payload 字段：

| 字段 | 说明 |
|---|---|
| `version` | 许可证协议版本，当前为 1 |
| `licenseId` | 许可证唯一编号 |
| `customer` | 授权客户 |
| `edition` | enterprise / professional |
| `maxAssets` | 最大资产额度 |
| `deploymentId` | 绑定的平台部署实例 |
| `issuedAt` | 签发时间 |
| `expiresAt` | 到期时间，空值表示永久 |
| `features` | 商业功能包 |
| `issuedBy` | 签发机构 |

许可证不包含私钥、数据库密码或客户业务数据。

## 4. 部署身份

平台首次启动时在 `cmdb_license_state` 中生成随机 Deployment ID：

```sql
CREATE TABLE cmdb_license_state (
  id integer PRIMARY KEY CHECK (id = 1),
  deployment_id text NOT NULL,
  license_token text NOT NULL DEFAULT '',
  activated_at timestamptz,
  activated_by text NOT NULL DEFAULT '',
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

多个网关副本共享 PostgreSQL 中的同一 Deployment ID。许可证必须与该 ID 一致，
因此不能直接复制到另一个客户部署使用。

## 5. 资产额度并发控制

所有新增资产最终经过 `cmdb.Service.CreateAsset`，Agent 首次注册也在 CMDB
服务层执行额度检查。

PostgreSQL 写入流程：

1. 开始资产插入事务；
2. 获取固定 advisory lock；
3. 在同一事务中查询 `cmdb_assets` 当前数量；
4. 从 `cmdb_license_state` 读取最新许可证；
5. 判断 `当前数量 + 本次新增数量 <= 授权额度`；
6. 通过后插入资产并提交事务。

这样即使网关有多个副本、多个用户同时导入，也不会突破额度。

## 6. 错误语义

新增资产额度不足时返回 HTTP `409`：

```json
{
  "code": "ASSET_LICENSE_LIMIT_EXCEEDED",
  "message": "免费版最多管理 200 个资产，当前已有 200 个，本次需要新增 1 个",
  "used": 200,
  "limit": 200,
  "requested": 1,
  "edition": "community"
}
```

CSV 导入会先计算本次真正新增的资产数量，额度不足时整批拒绝，避免部分导入。

## 7. 平台管理页面

系统管理新增“授权与用量”：

- 当前版本和状态；
- 已使用、总额度和剩余额度；
- 使用率环形图；
- 客户、许可证编号和有效期；
- 导入许可证；
- 下载授权申请文件；
- 80% 和 100% 额度提醒；
- 许可证被拒绝、过期或部署不匹配时显示明确原因。

## 8. 授权签发站

独立网站提供：

- 管理员账号密码登录；
- 客户名称、Deployment ID、额度、有效期、功能包录入；
- Ed25519 离线签名；
- 许可证复制和 `.license` 文件下载；
- 累计授权、有效授权、近期到期和累计容量统计；
- 签发记录持久化。

授权网站默认单副本运行，数据保存在 `/data/licenses.json`，可使用 Docker
Compose 命名卷或 Kubernetes PVC 持久化。管理员会话保存在进程内，授权站重启后
管理员需要重新登录。

## 9. 安全边界

- 授权站必须部署在内网或 IP 白名单后；
- 生产环境必须使用 HTTPS；
- 私钥文件不得提交 Git，不得挂载到正式平台；
- 管理员密码通过 Secret 注入，并定期轮换；
- 许可证只在平台激活时校验，不依赖外网；
- 开放源代码无法提供绝对防篡改 DRM，商业约束仍需配合许可证协议；
- 第三方不得使用 `CMDB Licensing Authority` 名义签发非官方许可证。

## 10. 验收标准

- 社区版第 200 个资产允许创建；
- 第 201 个资产被后端拒绝；
- 编辑已有资产不触发额度检查；
- 两副本并发创建不会超额；
- 商业许可证可导入并立即生效；
- 其他 Deployment ID 的许可证被拒绝；
- 篡改许可证签名被拒绝；
- 授权到期后进入宽限期，宽限结束后回退到 200 额度；
- 授权站可登录、签发、复制、下载和查询记录；
- 平台和授权站测试、构建、健康检查全部通过。
