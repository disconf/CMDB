# 物理网络链路治理设计

## 目标

CMDB 作为资产底账和关系枢纽，统一管理网络设备端口、服务器网卡以及二者之间的物理链路。采集与告警计算仍分别交给 SNMP Exporter 和 Prometheus，CMDB 负责发现、校准、绑定和拓扑展示。

## 数据模型

### 网络端口 `network_ports`

网络设备通过 SNMP 采集以下字段，并保存到资产扩展属性 `network_ports`：

- `ifIndex`、端口名称、描述和别名
- 管理状态、运行状态
- 速率、MAC 地址、PVID VLAN
- LLDP 对端设备、对端端口和对端 Chassis ID
- 最近采集时间

采集 OID 覆盖标准 IF-MIB、IF-MIB 扩展和 Q-BRIDGE-MIB，华为、H3C、Cisco、锐捷等设备可共用基础端口模型。

### 主机网卡 `network_interfaces`

Linux 主机通过 SSH 只读执行 `ip link` 和 `ip addr`，生成资产扩展属性 `network_interfaces`：

- 网卡名称、类型、MTU
- MAC 地址、IPv4 地址
- 管理状态和运行状态
- 最近采集时间

原有 `mac_addresses` 字段继续保留，用于兼容已有资产和检索。

### 物理链路 `connects-to`

人工确认后的链路使用资产关系 `connects-to` 保存：

- 源资产和源网卡
- 目标网络设备和目标端口
- 关系来源 `manual`
- 状态和最近确认时间

LLDP 发现的链路不重复写入人工关系，由拓扑服务在读取时实时计算，并标识为 `lldp`。这样可以避免自动发现覆盖人工校准结果。

## 后端接口

- `GET /api/v1/cmdb/network-devices`：网络设备及其端口汇总
- `GET /api/v1/cmdb/network-devices/{id}/ports`：端口清单
- `GET /api/v1/cmdb/assets/{id}/interfaces`：主机网卡及当前绑定
- `GET /api/v1/cmdb/network-links`：人工链路和 LLDP 链路
- `POST /api/v1/cmdb/network-links`：手工绑定网卡与交换机端口
- `DELETE /api/v1/cmdb/network-links/{id}`：解除人工绑定
- `GET /api/v1/topology/physical`：服务器与网络设备组成的物理拓扑

## 前端交互

### 网络设备

CMDB 的“网络设备”页签改为独立端口工作区：

- 左侧按设备筛选
- 右侧展示端口状态、速率、VLAN、MAC、LLDP 对端
- 统计设备数、端口总数、在线端口和 LLDP 邻居数

### 服务器

服务器资产详情抽屉增加“网卡与物理链路”区域：

- 展示采集到的网卡和 MAC/IP
- 将网卡绑定到已纳管交换机的端口
- 显示人工绑定或 LLDP 自动发现来源
- 支持解除人工绑定

### 拓扑中心

拓扑中心提供“业务关系拓扑”和“物理网络拓扑”两个模式。物理拓扑左侧为服务器，右侧为网络设备；链路显示源端、对端端口、绑定来源和最近采集时间。未纳管的 LLDP 邻居以“未纳管设备”节点展示。

## 采集与治理流程

1. 使用 Agent 与发现中的 SNMP 扫描纳管交换机并采集端口、VLAN 和 LLDP。
2. 使用 SSH 扫描补充服务器网卡清单。
3. 系统根据 LLDP 自动生成候选物理链路。
4. 运维人员在服务器资产详情中确认或手工绑定链路。
5. 拓扑中心按环境、状态和链路类型查看物理连接关系。

## 后续增强

- 在链路变更时写入独立事件并触发拓扑快照
- 增加交换机端口 MAC 地址表和服务器网卡 ARP 交叉校验
- 增加链路变更审批、备注和生命周期状态
- 接入机房、机柜、U 位，实现从拓扑跳转到物理位置

## 链路可信度与 MAC 交叉校验

交换机端口除了 LLDP 信息，还会尝试采集标准 BRIDGE-MIB 和 Q-BRIDGE-MIB 的 MAC 地址转发表：

- `dot1dBasePortIfIndex`
- `dot1dTpFdbPort`
- `dot1qTpFdbPort`

手工绑定时，系统将服务器网卡 MAC 与目标交换机端口学习到的 MAC 进行比较：

- MAC 匹配：标记为“链路已确认”，置信度 100
- 端口学习到其他 MAC：标记为“MAC 冲突”，进入人工复核
- 未采集到 MAC 或端口尚未学习：保持“待验证”
- LLDP 双向声明且对端已纳管：标记为“LLDP 已确认”

链路列表和物理拓扑会展示校验结论、置信度和证据说明。

## 变更历史与拓扑快照

资产关系变更会写入 `cmdb_asset_history` 的“物理链路”字段，可通过链路历史接口查看。人工新增或解除链路后，平台自动保存一次物理拓扑快照。

新增接口：

- `GET /api/v1/cmdb/network-links/history`
- `POST /api/v1/topology/snapshots`
- `GET /api/v1/topology/snapshots`
- `GET /api/v1/topology/snapshots/{id}`

拓扑快照保存节点数、链路数、环境、操作人、采集时间和完整拓扑 JSON。前端物理拓扑页面支持手工保存快照、查看历史快照和返回实时拓扑。

## 多厂商 FDB 适配

平台优先使用标准 `BRIDGE-MIB` 和 `Q-BRIDGE-MIB`。当厂商设备没有开放标准 FDB 视图时，按识别出的厂商追加私有表探测：

- 华为：`HUAWEI-L2MAM-MIB`
  - `hwDynFdbPort`：`1.3.6.1.4.1.2011.5.25.42.2.1.3.1.4`
  - `hwCfgFdbPort`：`1.3.6.1.4.1.2011.5.25.42.2.1.2.1.4`
- 华三：`HH3C-LswMAM-MIB`
  - `hh3cdot1qMacSearchPort`：`1.3.6.1.4.1.25506.8.35.3.1.1.3`
- 思科：优先使用标准 `BRIDGE-MIB` / `Q-BRIDGE-MIB`
- 锐捷：优先使用标准 `Q-BRIDGE-MIB`

解析器同时支持两种表索引：

- `mac-last`：索引尾部 6 个数字为 MAC，前一个数字为 VLAN，适用于标准 Bridge MIB。
- `mac-first`：索引开头 6 个数字为 MAC，后续数字为 VLAN，适用于华为和部分华三表。

成功读取 MAC 表后，资产会写入 `network_fdb_source`，前端网络设备详情显示采集来源；读取失败不会影响端口和 LLDP 数据，只会保持链路“待验证”。

## IP、MAC、ARP 与 VLAN 联合校验

交换机通过标准 `IP-MIB` 采集 ARP/邻居关系：

- `ipNetToMediaPhysAddress`：`1.3.6.1.2.1.4.22.1.2`
- `ipNetToPhysicalPhysAddress`：`1.3.6.1.2.1.4.35.1.4`

采集结果按接口索引写入网络端口的 `arpEntries`，包含 IP、MAC、VLAN、接口索引和资产关联。Linux 主机通过 SSH 执行 `ip neigh show`，把邻居表写入网卡的 `neighbors`，并汇总到 `network_neighbors` 扩展属性。

链路确认优先级：

1. 交换机 FDB/ARP 表 MAC 与服务器网卡 MAC 完全匹配：确认，置信度 100
2. 交换机 ARP IP 与服务器网卡 IPv4 匹配：确认，置信度 90
3. LLDP 双向声明且对端已纳管：LLDP 确认
4. 没有 ARP/FDB 证据：保持待验证
5. 端口存在其他 MAC 且没有目标 MAC：标记冲突并进入复核

VLAN 信息优先来自 Q-BRIDGE PVID 和 Q-BRIDGE FDB 索引；交换机和主机详情会同时展示 MAC、ARP 邻居和 VLAN 证据。

## VLAN 端口视图与网络异常中心

后端新增 `VLANInventory()`，按 PVID、Q-BRIDGE FDB 和 ARP VLAN 聚合成员端口，输出 VLAN 成员数、在线端口、学习 MAC 数、ARP 数和对应资产。接口：

- `GET /api/v1/cmdb/vlans`

拓扑中心新增“VLAN 视图”，以 VLAN 为中心节点展示成员端口、服务器资产、ARP 与 MAC 证据。

网络异常中心会基于当前 FDB、ARP、网卡和物理链路数据检测：

- 同一 MAC 在多个端口出现：`mac-port-flapping`
- 同一 IP 对应多个 MAC：`arp-ip-conflict`
- 资产 IP 与 ARP MAC 不一致：`arp-asset-mismatch`
- MAC 跨设备或端口漂移：`mac-drift`
- 人工链路与 FDB/ARP 冲突：`link-conflict`

接口：

- `GET /api/v1/cmdb/network-anomalies`

网络设备页面新增 VLAN 汇总、严重/关注异常数量和异常明细列表。

## 网络异常闭环

网络异常状态持久化在 `cmdb_network_anomaly_states`，支持：

- `open`：待处理
- `acknowledged`：已确认
- `resolved`：已关闭

接口：

- `POST /api/v1/cmdb/network-anomalies/{id}/acknowledge`
- `POST /api/v1/cmdb/network-anomalies/{id}/resolve`
- `POST /api/v1/cmdb/network-anomalies/{id}/ticket`
- `POST /api/v1/cmdb/network-anomalies/sync-alerts`

派单复用现有工单中心的告警工单同步机制，以异常 ID 去重。关闭异常时会同步关闭对应工单和告警。

告警同步会把网络异常作为 `cmdb_network_anomaly` 规则写入监控告警中心，并复用现有路由规则、通知渠道、静默和升级策略。异常恢复或人工关闭后，下一次同步会自动把对应告警标记为已恢复。

网络设备前端的异常列表支持：

- 确认异常
- 创建或复用工单
- 关闭异常
- 同步到告警中心
- 查看确认人、确认时间和处理备注
