# V1.5 ops-qa 环境部署与运维说明（CMDB 平台已上线）

> 说明：本文只记录架构、镜像、地址与操作步骤，**不含任何密码/密钥**。
> 密钥与凭据由部署者在集群 Secret 与主机本机文件（0600）中维护，不提交 Git。

## 1. 部署形态

| 项 | 值 |
|---|---|
| 集群 | K8s v1.28.15（3 master + 5 worker，172.28.69.161-168），Longhorn |
| 命名空间 | `ops-qa`（业务与中间件） |
| 镜像仓库 | Harbor `harbor.qa.bcavt.com`，项目 `cmdb` |
| 镜像 | `cmdb/gateway-bff:1.0.59`、`cmdb/web-portal:1.0.51` |
| 网关访问 | 集群内 Service `gateway`；Agent 专用 NodePort `30080` |

| API | https://cmdb-api.jzq.com:31443 |

## 2. 组件与中间件（ops-qa）
PostgreSQL(CNPG postgres-ha)、Redis Cluster、Kafka(KRaft)、Keycloak、MinIO、Vault、
APISIX 网关（http 31031 / https 31443）。CMDB 业务数据在 `ops_platform` 库。

## 3. 认证
- Keycloak realm `cmdb` 允许同一账号在多个浏览器/终端并发登录；SSO 空闲会话 8 小时，最大会话 10 小时，不启用单会话限制。
- 前端：Keycloak（realm `cmdb`，客户端 `cmdb-web`，PKCE S256），登录页走 https。
- 网关：配置 `KEYCLOAK_ISSUER_URL` 后校验 Keycloak JWT；hostAliases 指向节点以便访问 Keycloak。
- Agent：共享令牌（`AGENT_SHARED_TOKEN`，仅存 Secret/主机文件），上报 `/api/v1/agent/report`。
- 门户运行时认证配置：`KEYCLOAK_URL`、`KEYCLOAK_REALM`、`KEYCLOAK_CLIENT_ID`，由 web 服务动态提供 `/config.js`，避免构建期漏变量导致跳转旧地址。

## 4. 关键环境变量（网关 Secret：cmdb-gateway-env）
DATABASE_URL / KEYCLOAK_ISSUER_URL / AUTH_CACHE_TTL / AGENT_SHARED_TOKEN / AGENT_OFFLINE_AFTER / CMDB_NODE_EXPORTER_PORT / HTTP_ADDR / REMOTE_TERMINAL_REDIS_URL / REDIS_CLUSTER_MODE / REMOTE_TERMINAL_BUS / REMOTE_SESSION_LEASE_TTL

## 5. CMDB Agent（主机自动纳管）
- 二进制编译自 `apps/cmdb-agent`，安装到各主机 `/opt/cmdb-agent/cmdb-agent`。
- systemd 服务 `cmdb-agent`，环境文件 `/opt/cmdb-agent/cmdb-agent.env`（0600）：
  - `CMDB_GATEWAY_URL=http://127.0.0.1:30080`（网关 NodePort，宿主机免 DNS）
  - `CMDB_AGENT_TOKEN=...`（与网关一致）
  - `CMDB_AGENT_TYPE=virtual-machine|physical-server`（决定资产归类）
  - `CMDB_REPORT_INTERVAL=60s`
- Agent 每 60s 上报主机信息；网关按 ID 合并资产、按类型归类；超时（默认 3 分钟）自动标离线。
- 安装/批量部署脚本见 `deploy/agent/`（需要自备二进制与令牌，勿把令牌提交 Git）。

## 6. 更新发布流程（网关/门户镜像）
1. 修改代码 → 本地编译产物 → 经 `cmdb-image-builder`（集群内 DinD，临时 Pod）构建并推送 Harbor：
   `docker build -f <ctx>/Dockerfile -t harbor.qa.bcavt.com/cmdb/gateway-bff:1.0.0 <ctx> && docker push ...`
2. `kubectl rollout restart deployment/gateway -n ops-qa`（Deployment 已设 imagePullPolicy: Always）。
3. 校验：`curl -k https://cmdb-api.jzq.com:31443/api/v1/ready`。

## 7. 上线阻断/注意
- 证书为内部 CA（自签），公网/其他同事访问需安装 `ca.crt` 或替换正式证书（APISIX SSL 对象 + 各端配置）。
- APISIX 网关当前用 Harbor 内 `inchtek/apache/apisix:3.17.0-ubuntu`。
- Gateway Deployment 必须通过 `envFrom.secretRef` 注入 `cmdb-gateway-env`；仅有 Downward API 的 `POD_NAME` 会导致网关退化为内存模式。
- 受控批量远程执行仅允许服务端只读白名单，提交后必须审批；SSH 输出和审批过程写入数据库与审计日志。
- 远程终端命令、文件上传下载、会话关闭和结果输出持久化到 PostgreSQL；支持历史会话查询、命令时间线回放，网关重启后录像仍可恢复。
- 受控运维支持交互式 WebSSH/PTY、终端窗口缩放和逐屏原始终端录像；高风险命令进入平台管理员审批，批准后仅放行一次，拒绝或超时均不执行，审批与会话录像均写入数据库和审计日志。
- 终端安全策略支持用户、角色和全局优先级，提供标准、严格、应急快捷模板；管理员可批量分发到用户或角色，策略保存、删除和批量分发均可在页面查看审计记录。
- 录像过期清理在网关启动时执行，并由后台任务每 24 小时复查一次；每个会话按生效策略中的录像保留天数清理终端事件。
- APISIX 的 `cmdb-web`、`cmdb-api` 路由必须设置 `enable_websocket: true`；对应声明见 `deploy/k8s/apisix-cmdb-websocket.yaml`。
- Kubernetes 采集使用只读 ServiceAccount `cmdb-k8s-reader`，ClusterRole 仅授予核心、apps、networking、batch 资源的 `get/list`。
- node_exporter 一键管理由网关镜像内置 `v1.11.1` Linux 二进制，通过 SSH + systemd 部署，目标主机无需访问外网。

## 演示数据与真实数据

生产环境统一设置：

```text
CMDB_ENABLE_DEMO_DATA=false
```

关闭后，系统不再生成演示资产、演示发现任务、演示告警、演示工单、演示发布、演示分析记录、演示执行历史或演示仪表盘数据。资产模型、任务模板、工具定义和知识库等基础配置继续保留。真实数据只来自 Agent、SSH、node_exporter、SNMP、Kubernetes 采集和 Prometheus/Alertmanager 回写。
## 8. 远程运维多实例发布（v1.0.51）

- 网关 Deployment 保持 2 个副本，并通过 Downward API 注入 `POD_NAME` 作为 `GATEWAY_INSTANCE_ID`。
- `cmdb-gateway-env` 增加：

```text
REMOTE_TERMINAL_REDIS_URL=redis://:PASSWORD@redis-cluster-leader.ops-qa.svc.cluster.local:6379/0
REDIS_CLUSTER_MODE=true
REMOTE_TERMINAL_BUS=enabled
REMOTE_SESSION_LEASE_TTL=45s
```

- 任意副本可接入同一远程会话；owner 持有真实 SSH 连接，其他副本通过 Redis 转发。
- owner 失联后租约到期，会话自动标记为 `interrupted`，浏览器代理端自动关闭。
- 详细设计见 `docs/design/remote-access-multi-instance.md`。


## 9. 采集计划发布（v1.0.52 / v1.0.45）

- “Agent 与发现”新增“采集计划”标签页，支持 node_exporter、SSH、SNMP 三类周期性采集。
- 支持 5/15/30 分钟、1/6/12 小时、1 天周期，可暂停、恢复、编辑、删除和立即执行。
- 计划持久化在 PostgreSQL 表 `discovery_schedules`；Gateway 使用 `FOR UPDATE SKIP LOCKED` 抢占到期计划，两个副本不会重复执行。
- 每次执行生成独立发现任务，可在任务结果页查看发现、入库、合并、冲突和失败明细；需要审批的结果保持待审批状态。
- 部署时必须确认 gateway 容器同时具备：

```text
spec.template.spec.containers[gateway].envFrom:
  - secretRef:
      name: cmdb-gateway-env
spec.template.spec.containers[gateway].env:
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
```

- 关联设计文档：`docs/design/Agent与发现模块设计.md`。
## 10. 采集质量与离线告警（v1.0.54 / v1.0.46）

- Agent 与发现新增采集质量标签页，汇总 Agent 在线率、Exporter 覆盖率、任务/计划成功率和待处理问题。
- 新增只读接口 GET /api/v1/discovery/quality，数据实时来自 CMDB、Agent 心跳、发现任务和采集计划。
- Prometheus 建议配置 up == 0 和 absent(up) 规则，覆盖 node_exporter 抓取失败与目标缺失；Alertmanager Webhook 继续回写 CMDB 资产状态。


## 11. Agent 生命周期与凭据中心（v1.0.57 / v1.0.49）

- “Agent 部署”升级为生命周期控制台：新增版本台账、在线/离线统计、当前/过期/未知版本识别，以及按过期 Agent、手工 IP/CIDR、项目组、标签选择目标。
- 批量升级只允许升级到 Gateway 当前实际可服务的 `CMDB_AGENT_VERSION`，不提供无法校验的历史二进制；升级本质为幂等重装。
- Agent 安装、升级、卸载均改为登录用户权限校验并写入审计日志，修复此前使用 Agent 共享令牌导致前端操作返回 `UNAUTHORIZED` 的问题。
- 新增 `GET /api/v1/discovery/agent-versions`，返回当前版本、版本分布和逐台 Agent 版本台账。
- 新增 `POST /api/v1/discovery/agent-upgrade`；安装与卸载支持指定 Vault SSH 凭据。
- “凭据中心”支持 SSH 账号密码、SNMP v2c Community，新增分组和说明字段；密码/Community 仅写入 Vault，接口不回显。
- node_exporter 卸载也支持引用同一 SSH 凭据，避免安装与卸载使用不同账号。
- 验证结果：Gateway Go 全量测试、`go vet` 通过；Web 30 项前端测试和生产构建通过；`ops-qa` 两副本滚动发布完成。

## 12. Agent 部署任务中心（v1.0.58 / v1.0.50）

- 新增只读预检查：目标主机 SSH 可连接后检查 root 权限、systemd、curl、/opt 可用磁盘和 Gateway 下载通道；检查过程不修改主机。
- 新增 `agent_deployments` 持久化表，安装、升级、卸载和失败重试都会保留任务状态、参数、逐台结果、发起人与时间。
- 新增查询与重试接口：
  - `GET /api/v1/discovery/agent-deployments`
  - `GET /api/v1/discovery/agent-deployments/{id}`
  - `POST /api/v1/discovery/agent-deployments/{id}/retry`
  - `POST /api/v1/discovery/agent-precheck`
- 前端 Agent 部署页增加预检查结果、部署任务历史和逐台结果弹窗；失败任务可直接重试失败主机。
- 升级仍只允许目标为 Gateway 当前实际服务的 `CMDB_AGENT_VERSION`，不会伪造历史二进制。
- 验证结果：Gateway Go 全量测试与 `go vet` 通过，Web 生产构建通过，`ops-qa` 网关/门户双副本滚动发布成功。

## 13. Agent 健康巡检与异常自愈（v1.0.59 / v1.0.51）

- “Agent 与发现”新增“健康巡检”标签页，支持单 IP 和 IPv4 CIDR 巡检，实时展示正常、警告、严重数量以及逐台评分。
- 巡检项覆盖：Agent 二进制/服务/自启状态、版本、重启次数、Gateway 可达性、根分区、内存、负载、node_exporter 实际监听端口与最近 journal。
- 新增 `agent_health_checks` 表持久化巡检参数、逐台结果、问题建议、评分统计和自愈记录。
- 新增接口：
  - `POST /api/v1/discovery/agent-health-checks`：发起只读健康巡检。
  - `GET /api/v1/discovery/agent-health-checks`：查询巡检历史。
  - `GET /api/v1/discovery/agent-health-checks/{id}`：查看单次巡检详情。
  - `POST /api/v1/discovery/agent-health-checks/{id}/remediate`：执行白名单自愈并自动复检。
- 自愈动作仅允许：`restart-agent`、`enable-agent`、`reset-agent`、`restart-node-exporter`、`reinstall-agent`；后端不接受任意命令。
- 巡检与自愈均要求平台登录鉴权，分别使用 `discovery:view` / `discovery:manage` 权限，并写入审计日志；SSH 密码继续只从 Vault/服务端 Secret 解析，不写入任务记录。
- 验证结果：Gateway Go 全量测试与 `go vet` 通过，Web 30 项测试和生产构建通过；后续发布 `ops-qa` 网关/门户双副本。
