## 3. 认证
- Keycloak realm `cmdb` 允许同一账号在多个浏览器/终端并发登录；SSO 空闲会话 8 小时，最大会话 10 小时，不启用单会话限制。
- 前端：Keycloak（realm `cmdb`，客户端 `cmdb-web`，PKCE S256），登录页走 https。
- 网关：配置 `KEYCLOAK_ISSUER_URL` 后校验 Keycloak JWT；hostAliases 指向节点以便访问 Keycloak。
- Agent：共享令牌（`AGENT_SHARED_TOKEN`，仅存 Secret/主机文件），上报 `/api/v1/agent/report`。
- 门户运行时认证配置：`KEYCLOAK_URL`、`KEYCLOAK_REALM`、`KEYCLOAK_CLIENT_ID`，由 web 服务动态提供 `/config.js`，避免构建期漏变量导致跳转旧地址。

## 5. CMDB Agent（主机自动纳管）
- 二进制编译自 `apps/cmdb-agent`，安装到各主机 `/opt/cmdb-agent/cmdb-agent`。
- systemd 服务 `cmdb-agent`，环境文件 `/opt/cmdb-agent/cmdb-agent.env`（0600）：
  - `CMDB_GATEWAY_URL=http://127.0.0.1:30080`（网关 NodePort，宿主机免 DNS）
  - `CMDB_AGENT_TOKEN=...`（与网关一致）
  - `CMDB_AGENT_TYPE=virtual-machine|physical-server`（决定资产归类）
  - `CMDB_REPORT_INTERVAL=60s`
- Agent 每 60s 上报主机信息；网关按 ID 合并资产、按类型归类；超时（默认 3 分钟）自动标离线。
- 安装/批量部署脚本见 `deploy/agent/`（需要自备二进制与令牌，勿把令牌提交 Git）。

## 6. 更新发布流程（网关/门户镜像）
1. 修改代码 → 本地编译产物 → 经 `cmdb-image-builder`（集群内 DinD，临时 Pod）构建并推送 Harbor：
   `docker build -f <ctx>/Dockerfile -t harbor.qa.bcavt.com/cmdb/gateway-bff:1.0.0 <ctx> && docker push ...`
2. `kubectl rollout restart deployment/gateway -n ops-qa`（Deployment 已设 imagePullPolicy: Always）。
3. 校验：`curl -k https://cmdb-api.jzq.com:31443/api/v1/ready`。

## 7. 上线阻断/注意
- 证书为内部 CA（自签），公网/其他同事访问需安装 `ca.crt` 或替换正式证书（APISIX SSL 对象 + 各端配置）。
- APISIX 网关当前用 Harbor 内 `inchtek/apache/apisix:3.17.0-ubuntu`。
- Gateway Deployment 必须通过 `envFrom.secretRef` 注入 `cmdb-gateway-env`；仅有 Downward API 的 `POD_NAME` 会导致网关退化为内存模式。
- 受控批量远程执行仅允许服务端只读白名单，提交后必须审批；SSH 输出和审批过程写入数据库与审计日志。
- 远程终端命令、文件上传下载、会话关闭和结果输出持久化到 PostgreSQL；支持历史会话查询、命令时间线回放，网关重启后录像仍可恢复。
- 受控运维支持交互式 WebSSH/PTY、终端窗口缩放和逐屏原始终端录像；高风险命令进入平台管理员审批，批准后仅放行一次，拒绝或超时均不执行，审批与会话录像均写入数据库和审计日志。
- 终端安全策略支持用户、角色和全局优先级，提供标准、严格、应急快捷模板；管理员可批量分发到用户或角色，策略保存、删除和批量分发均可在页面查看审计记录。
- 录像过期清理在网关启动时执行，并由后台任务每 24 小时复查一次；每个会话按生效策略中的录像保留天数清理终端事件。
- APISIX 的 `cmdb-web`、`cmdb-api` 路由必须设置 `enable_websocket: true`；对应声明见 `deploy/k8s/apisix-cmdb-websocket.yaml`。
- Kubernetes 采集使用只读 ServiceAccount `cmdb-k8s-reader`，ClusterRole 仅授予核心、apps、networking、batch 资源的 `get/list`。
- node_exporter 一键管理由网关镜像内置 `v1.11.1` Linux 二进制，通过 SSH + systemd 部署，目标主机无需访问外网。

## 8. 远程运维多实例发布（v1.0.51）

- 网关 Deployment 保持 2 个副本，并通过 Downward API 注入 `POD_NAME` 作为 `GATEWAY_INSTANCE_ID`。
- `cmdb-gateway-env` 增加：

```text
REMOTE_TERMINAL_REDIS_URL=redis://:PASSWORD@redis-cluster-leader.ops-qa.svc.cluster.local:6379/0
REDIS_CLUSTER_MODE=true
REMOTE_TERMINAL_BUS=enabled
REMOTE_SESSION_LEASE_TTL=45s
```

- 任意副本可接入同一远程会话；owner 持有真实 SSH 连接，其他副本通过 Redis 转发。
- owner 失联后租约到期，会话自动标记为 `interrupted`，浏览器代理端自动关闭。
- 详细设计见 `docs/design/remote-access-multi-instance.md`。


## 9. 采集计划发布（v1.0.52 / v1.0.45）

- “Agent 与发现”新增“采集计划”标签页，支持 node_exporter、SSH、SNMP 三类周期性采集。
- 支持 5/15/30 分钟、1/6/12 小时、1 天周期，可暂停、恢复、编辑、删除和立即执行。
- 计划持久化在 PostgreSQL 表 `discovery_schedules`；Gateway 使用 `FOR UPDATE SKIP LOCKED` 抢占到期计划，两个副本不会重复执行。
- 每次执行生成独立发现任务，可在任务结果页查看发现、入库、合并、冲突和失败明细；需要审批的结果保持待审批状态。
- 部署时必须确认 gateway 容器同时具备：

```text
spec.template.spec.containers[gateway].envFrom:
  - secretRef:
      name: cmdb-gateway-env
spec.template.spec.containers[gateway].env:
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
```

- 关联设计文档：`docs/design/Agent与发现模块设计.md`。

## 17. 事件驱动刷新、拓扑影响分析与事件总线告警（v1.0.65 / 1.0.55）

- Gateway 新增内部资产事件消费者，订阅 `cmdb.asset.changed.v1` 与 `cmdb.asset.status.v1`；每个副本使用独立 Consumer Group，确保任一副本处理写入后，其他副本也会刷新 PostgreSQL 读取模型。
- 消费到已提交资产事件后重新加载 CMDB 资产、模型和历史，并立即失效拓扑缓存；拓扑读取采用 15 秒缓存，避免每次页面请求都全量重算关系图。
- 拓扑影响分析升级为定向 BFS：
  - 输出上下游方向、距离和完整影响路径；
  - 汇总严重、关注、健康三类影响节点；
  - 默认按严重程度、距离和名称排序，异常节点优先。
- `/metrics` 新增事件总线指标：
  - `cmdb_event_outbox_pending`
  - `cmdb_event_outbox_retrying`
  - `cmdb_event_outbox_published_24h`
  - `cmdb_event_outbox_last_publish_timestamp_seconds`
