## 3. 认证
- Keycloak realm `cmdb` 允许同一账号在多个浏览器/终端并发登录；SSO 空闲会话 8 小时，最大会话 10 小时，不启用单会话限制。
- 前端：Keycloak（realm `cmdb`，客户端 `cmdb-web`，PKCE S256），登录页走 https。
- 网关：配置 `KEYCLOAK_ISSUER_URL` 后校验 Keycloak JWT；hostAliases 指向节点以便访问 Keycloak。
- Agent：共享令牌（`AGENT_SHARED_TOKEN`，仅存 Secret/主机文件），上报 `/api/v1/agent/report`。
- 门户运行时认证配置：`KEYCLOAK_URL`、`KEYCLOAK_REALM`、`KEYCLOAK_CLIENT_ID`，由 web 服务动态提供 `/config.js`，避免构建期漏变量导致跳转旧地址。

## 4. 关键环境变量（网关 Secret：cmdb-gateway-env）
资源规格：请求 `cpu 250m / memory 1Gi`，上限 `cpu 2 / memory 5Gi`，`GOMEMLIMIT=3500MiB`。Go 的内存上限必须明显低于容器内存上限，否则宿主 cgroup 会先 OOM 杀掉进程（历史故障：4Gi 上限 + 3500MiB 软上限约每 10 分钟被 OOM 一次）。
探针：就绪 `/api/v1/ready` 3s 超时 × 4 次，存活 `/api/v1/health` 3s 超时 × 5 次，避免高峰期因 GC 抖动被误杀。
DATABASE_URL / KEYCLOAK_ISSUER_URL / AUTH_CACHE_TTL / AGENT_SHARED_TOKEN / AGENT_OFFLINE_AFTER / CMDB_NODE_EXPORTER_PORT / HTTP_ADDR / REMOTE_TERMINAL_REDIS_URL / REDIS_CLUSTER_MODE / REMOTE_TERMINAL_BUS / REMOTE_SESSION_LEASE_TTL / PROMETHEUS_URL / ALERTMANAGER_URL / RELEASE_WEBHOOK_TOKEN / RANCHER_URL / RANCHER_TOKEN / RANCHER_DASHBOARD_URL / RANCHER_INSECURE_SKIP_VERIFY / RELEASE_EXECUTOR_URL / RELEASE_EXECUTOR_TOKEN

## 5. CMDB Agent（主机自动纳管）
- 二进制编译自 `apps/cmdb-agent`，安装到各主机 `/opt/cmdb-agent/cmdb-agent`。
- systemd 服务 `cmdb-agent`，环境文件 `/opt/cmdb-agent/cmdb-agent.env`（0600）：
  - `CMDB_GATEWAY_URL=http://127.0.0.1:30080`（网关 NodePort，宿主机免 DNS）
  - `CMDB_AGENT_TOKEN=...`（与网关一致）
  - `CMDB_AGENT_TYPE=virtual-machine|physical-server`（决定资产归类）
  - `CMDB_REPORT_INTERVAL=60s`
- Agent 每 60s 上报主机信息；网关按 ID 合并资产、按类型归类；超时（默认 3 分钟）自动标离线。
- 安装/批量部署脚本见 `deploy/agent/`（需要自备二进制与令牌，勿把令牌提交 Git）。

## 7. 上线阻断/注意
- 证书为内部 CA（自签），公网/其他同事访问需安装 `ca.crt` 或替换正式证书（APISIX SSL 对象 + 各端配置）。
- APISIX 网关当前用 Harbor 内 `inchtek/apache/apisix:3.17.0-ubuntu`。
- Gateway Deployment 必须通过 `envFrom.secretRef` 注入 `cmdb-gateway-env`；仅有 Downward API 的 `POD_NAME` 会导致网关退化为内存模式。
- 受控批量远程执行仅允许服务端只读白名单，提交后必须审批；SSH 输出和审批过程写入数据库与审计日志。
- 远程终端命令、文件上传下载、会话关闭和结果输出持久化到 PostgreSQL；支持历史会话查询、命令时间线回放，网关重启后录像仍可恢复。
- 受控运维支持交互式 WebSSH/PTY、终端窗口缩放和逐屏原始终端录像；高风险命令进入平台管理员审批，批准后仅放行一次，拒绝或超时均不执行，审批与会话录像均写入数据库和审计日志。
- 终端安全策略支持用户、角色和全局优先级，提供标准、严格、应急快捷模板；管理员可批量分发到用户或角色，策略保存、删除和批量分发均可在页面查看审计记录。
- 录像过期清理在网关启动时执行，并由后台任务每 24 小时复查一次；每个会话按生效策略中的录像保留天数清理终端事件。
- APISIX 的 `cmdb-web`、`cmdb-api` 路由必须设置 `enable_websocket: true`；对应声明见 `deploy/k8s/apisix-cmdb-websocket.yaml`。
- Kubernetes 采集使用只读 ServiceAccount `cmdb-k8s-reader`，ClusterRole 仅授予核心、apps、networking、batch 资源的 `get/list`。
- node_exporter 一键管理由网关镜像内置 `v1.11.1` Linux 二进制，通过 SSH + systemd 部署，目标主机无需访问外网。

## 8. 远程运维多实例发布（v1.0.51）

- 网关 Deployment 保持 2 个副本，并通过 Downward API 注入 `POD_NAME` 作为 `GATEWAY_INSTANCE_ID`。
- `cmdb-gateway-env` 增加：

```text
REMOTE_TERMINAL_REDIS_URL=redis://:PASSWORD@redis-cluster-leader.ops-qa.svc.cluster.local:6379/0
REDIS_CLUSTER_MODE=true
REMOTE_TERMINAL_BUS=enabled
```

## 9. 采集计划发布（v1.0.52 / v1.0.45）

- “Agent 与发现”新增“采集计划”标签页，支持 node_exporter、SSH、SNMP 三类周期性采集。
- 支持 5/15/30 分钟、1/6/12 小时、1 天周期，可暂停、恢复、编辑、删除和立即执行。
- 计划持久化在 PostgreSQL 表 `discovery_schedules`；Gateway 使用 `FOR UPDATE SKIP LOCKED` 抢占到期计划，两个副本不会重复执行。

```text
spec.template.spec.containers[gateway].envFrom:
  - secretRef:
      name: cmdb-gateway-env
spec.template.spec.containers[gateway].env:
  - name: POD_NAME
    valueFrom:
      fieldRef:
        fieldPath: metadata.name
```

## 执行审计与受控回滚

- `GET /api/v1/aiops/execution-stats` 汇总演练、真实执行、待审批、运行中、成功、失败和执行成功率，并按 Runbook 聚合。

- Runbook 策略新增 `liveDailyLimit`、`liveCooldownMinutes` 和 `requireRollback`，用于限制真实变更的每日次数、冷却间隔和回滚就绪要求。

- 预检接口返回逐项 `pass/warn/fail`，不通过时给出最早可执行时间。
- 审批通过后的真实执行会再次执行同一组服务端门禁，不能通过直接调用接口绕过。
- 演练模式不占用真实执行额度，也不会触发冷却。

## 变更计划快照与执行后验证

- 每次申请 Runbook 审批时固化 `changePlan`，保存目标资产、环境、执行方式、前置条件、执行步骤、回滚方案、验证要求和计划人。
- 回滚申请也生成独立变更计划，并关联原执行记录。
- 任务结束后，系统读取目标资产的 Prometheus/监控聚合状态进行验证。
- 验证状态包括 `pending`、`passed`、`failed`；演练执行直接标记为已通过，不产生真实变更。
- 验证失败时前端提示可申请受控回滚，但不会自动执行回滚。
- 变更计划、验证结果和执行日志均随 AIOps 执行记录持久化，可用于审批、复盘和审计。

## 真实变更冻结与全局急停

- `GET /api/v1/aiops/change-control`：查询平台真实变更总开关、冻结状态、冻结原因和截止时间。
- `PUT /api/v1/aiops/change-control`：管理员更新总控配置并写入审计。
- `liveEnabled=false` 时，所有真实变更 Runbook 在预检和审批执行阶段都会被拒绝。
- `frozen=true` 时，所有真实变更被冻结；支持填写原因和可选截止时间，到期后自动解除。

## 资产投影实时化与跨副本一致

- 资产变更事件（`cmdb.asset.changed.v1`、`cmdb.asset.status.v1`）现在会即时刷新 Neo4j 与 OpenSearch，
  无需再手工点“重建投影”；事件里取不到资产编号时静默跳过。
- Kafka 消费组下每条资产事件只会被某一个网关副本消费，其余副本的内存资产缓存不会更新。
  新增 `RunAssetCacheRefresh` 后台任务（`CMDB_ASSET_RELOAD_INTERVAL_SEC`，默认 60 秒）定期从 PostgreSQL 重载，
  避免两个副本返回不一致的资产数据。
- 全量重建现在会收敛到 PostgreSQL 快照：先按显式映射校正 OpenSearch 索引
  （`ID` 必须是精确 keyword，否则 `_delete_by_query` 的 `terms` 会静默匹配不到任何文档并清空索引），
  再写入全部资产，最后删除已不存在的图节点与检索文档。
- 单资产删除走 `_bulk` 的 `delete` 动作 + Neo4j `DETACH DELETE`，同样不依赖 URL 路径拼接。

## 可观测性：日志与链路追踪

- **Loki 日志**：`deploy/k8s/observability-logging.yaml` 部署单副本 Loki（Longhorn 20Gi，保留 7 天）

  不留任何额外开销（`internal/observability`）。
  采样率由 `OTEL_TRACES_SAMPLER_ARG` 控制（默认 1.0，即全量采集）。

## 前端全站审计修复（2026-10-16）

用无头浏览器把 14 个一级菜单及其内部功能页签逐页跑了一遍（176 个页面/页签），
把后端 410 个路由与前端 281 处调用逐条比对，发现并修复三个真实缺陷：

1. **CI/CD 与发布 → 资源总览整页空白**：后端在缓存深拷贝时用 `append([]T(nil), ...)` 把空切片变成 `null`，
   前端对 `resources.argoCD.items` 取 `.length` 抛 `TypeError`，Vue 渲染中断导致整个页面（含页签导航）消失，
   连"资源关系""监控联动"都点不进去。后端改用始终返回非 nil 的 `cloneSlice`，前端同时做响应归一化兜底。
2. **全局态势仪表盘全部显示 0**：`GET /api/v1/dashboard/overview` 没有调用 `authorize()`，
   而前端 `fetchDashboardOverview` 也没带 `Authorization` 头；服务端在无身份时按"最小数据范围"把指标清零，
   于是匿名请求返回一份全 0 的正常响应。现在后端强制鉴权（匿名 401），前端补上 Bearer 头。
3. **仪表盘 6 个面板只有演示数据**：`Capacity/Health/Topology/AlertTrend/Jobs/Timeline` 在真实模式下是硬编码空数组。
   现在全部改为真实数据：资产构成占比、按类别在线率、项目组/资产类型/环境/采集来源/机房位置五层分布、
   近 24 小时告警趋势（12 个 2 小时分桶）、活动任务（来自任务中心）、运维操作时间线（来自审计日志）。

审计结论：全站 14 个页面、176 个页面/页签均能正常渲染，无空白页；
唯一失败接口为 `/api/v1/credentials` 返回 503（Vault Token 过期，见下）。
